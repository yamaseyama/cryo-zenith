# 補助金・助成金 AI診断システム (MVP版)

本プロジェクトは、中小企業や個人事業主向けに「自社で申請可能な補助金・助成金」を簡単に探し出し、AIに相談できるWebアプリケーションの最小実行可能プロダクト（MVP）です。将来的なSaaS化・事業化を見据えたアーキテクチャで設計されています。

---

## 🎯 プロジェクトの目的と提供価値
- **目的**: 煩雑で探しにくい補助金情報を一元化し、LLM（大規模言語モデル）の力を使ってユーザーに最適な支援策を提示・相談可能にする。
- **提供価値**: 入力フォームによる簡単な診断と、AIチャットを通じた具体的な相談体験の提供。

---

## 🏗 システム構成

本システムは、セキュリティと拡張性を考慮し、フロントエンドとバックエンドを分離した実務的な構成を採用しています。

### 基本アーキテクチャ
- **フロントエンド (HTML/CSS/Vanilla JS)**
  - ユーザーインターフェース。ユーザーからの診断情報の入力と、バックエンドAPIへのリクエストを担当。
  - APIキーなどの機密情報を一切保持しないセキュアな設計。
- **バックエンド (Node.js / Express)**
  - DBアクセス、ビジネスロジック（スコアリング機能）、OpenAI APIとの通信を隠蔽。
  - 外部APIへのエンドポイントを提供し、CORS設定などによる適切なアクセス制御を実施。
- **データベース (PostgreSQL / Supabase)**
  - クラウドベースのリレーショナル・データベース。将来のスケーリングに耐えうる設計。
  - `subsidy_programs` テーブルで補助金の基本情報から募集ステータスまでを一元管理。

### 主要ファイルと役割
- `public/index.html` : アプリケーションのUI本体。
- `public/app.js`     : フロントエンドの非同期通信・DOM操作ロジック。
- `server.js`         : 診断API (`/api/diagnose`) と 相談API (`/api/consult`) を提供するNode.jsサーバー。
- `scoring.js`        : ユーザーの入力内容とDBの補助金情報のマッチング（スコアリング）ロジック。
- `llm.js`            : OpenAI APIと連携し、補助金データを基に回答を生成するビジネスロジック。
- `database.js`       : PostgreSQL (Supabase) への接続とクエリ実行ロジック。

## 🔄 データ基盤と更新フロー

本システムは、手動のデータに加え、国が提供する「JグランツAPI」から網羅的に補助金情報を取得する基盤を持っています。

### 現在の収録データ数（基準日：2026/3/10時点）
- **収録件数**: **179件**（国のJグランツAPIより取得・厳選した「現在募集中」の補助金・助成金データ）

### データ更新の頻度と運用（自動・手動）
- **現状（MVP版）**: 更新はローカル環境から**手動**でバッチ・スクリプトを実行してDBを同期する運用です（推奨：週1〜2回程度）。
- **将来（SaaS版）**: GitHub ActionsやSupaBaseのcron機能を活用し、週次や日次で**完全自動**で情報が同期されるクーロン・ジョブ化を想定しています。

### 具体的な手動データ更新プロセス
`package.json` に定義された以下のバッチ処理コマンドを用いて、データベースを最新に保ちます。

1. **`npm run db:fetch` (データ取得)**
   - `fetch_jgrants.js` を実行。JグランツAPIから「補助金」「助成金」「IT導入」などの幅広いキーワードを利用して、最新の公募情報を全件取得します。
   - Jグランツから消えた（募集終了した）プログラムを自動検出し、ステータスを管理します。
   - 取得結果を一度ローカルの `data/programs.json` に出力します。
2. **`npm run db:update` (データベース反映)**
   - `update_programs.js` を実行。`programs.json` のデータをPostgreSQLにUPSERT（存在しなければINSERT、あればUPDATE）で流し込みます。
   - 重複を防ぎつつ、各補助金情報の「最新確認日時 (`last_verified_at`)」を更新します。
3. **`npm run db:check` (鮮度管理)**
   - `check_freshness.js` を実行。一定期間更新されていないデータに対して警告を出したり、自動的にステータスを「期限切れ (stale)」にするなど、データの品質を維持します。

## 🤖 AIハイブリッド診断アーキテクチャ

本システムでは、実際のSaaS開発現場でも主流となっている「ハイブリッド構成」を採用し、**正確性**と**ユーザー体験の向上**を両立させています。コアロジックをプログラムで固め、高度な対話部分のみをAIに任せることで致命的な誤検知（ハルシネーション）を防ぎます。

1. **ベースの診断・スコアリング ＝ AI不使用 (正確性と速度を担保)**
   - ユーザーの入力（業種・目的・規模）と数十〜数百の補助金の条件マッチング（`scoring.js`）は、通常のプログラムで瞬時に計算しています。
   - 対象外の補助金をAIが誤っておすすめしてしまうリスクを防ぎます。
2. **適合理由の解説・総評 ＝ AIを活用 (体験の向上)**
   - プログラムで選別した上位の補助金に対してのみ、OpenAI APIを使って「なぜこの企業におすすめなのか」を自然な日本語（コンサルタント風）に変換させています。
3. **個別相談チャット ＝ AIを活用 (個別最適化)**
   - 診断結果上の「💬 AIに相談する」機能では、対象補助金の正確な情報（対象者、補助上限など）をプロンプトに含めた上でOpenAIと会話させ、安全かつ柔軟にユーザーの疑問に回答します。

## 🔌 API利用構成とその目的

本MVPシステムでは、以下の2つの外部APIを活用してコア機能を実現しています。

1. **OpenAI API (`gpt-4o-mini`)**
   - **用途**: AIによる補助金相談チャット機能
   - **詳細**: フロントエンドからの相談内容（＋診断結果リストの一部）を受け取り、バックエンド側（`llm.js`）でプロンプトを構築してOpenAIにリクエストを送信。ユーザーに寄り添った的確な支援アドバイスを生成して返却します。
   
2. **JグランツAPI**
   - **用途**: 補助金情報の網羅的なデータベース収集
   - **詳細**: バックエンドのバッチ処理（`fetch_jgrants.js`）にて利用。国が公式に提供しているAPIから「募集中」の全案件情報（目的、対象地域、金額等）を定期的に一括取得し、自社DBのマスターデータを最新状態に保つために使用しています。

## 🔐 セキュリティ設定・環境変数

APIキーなどの機密情報はコードベースには含めず、`.env` ファイルを通じて環境変数としてバックエンド環境に読み込ませます。絶対にGitHubなどの公開リポジトリにはプッシュしないでください。

### 必要な環境変数 (`.env`)
```env
# サーバー起動ポート
PORT=3000

# OpenAI API Key (LLMによるAI相談機能に必須)
OPENAI_API_KEY=sk-xxxx...

# Supabase (PostgreSQL) 接続文字列
DATABASE_URL=postgresql://postgres:[PASSWORD]@db.[PROJECT_REF].supabase.co:5432/postgres
```

## 🚀 将来の拡張性（SaaS化に向けて）

MVPの次のステップとして、事業化・SaaS化を見据えた以下の拡張が可能な設計となっています。

1. **ユーザー認証基盤の導入**
   - Supabase Auth 等を活用し、ユーザー登録・ログイン機能を実装。
   - 診断履歴やチャットの履歴を保存し、「お気に入り補助金」機能などを提供可能。
2. **本番環境へのデプロイ**
   - 現在のコードは、Vercel (フロントエンド/バックエンド一体) や Render/Heroku (バックエンドのみデプロイ) など、モダンなPaaSに容易にデプロイ可能です。
3. **データソースの更なる拡張**
   - Jグランツだけでなく、各自治体独自のスクレイピングデータや、有料の補助金データAPIプロバイダからの定期取得バッチの並行稼動が可能です。
4. **より高度なマッチングアルゴリズム**
   - `scoring.js` のルールベースのマッチングに加え、ユーザーの企業情報（テキスト）と補助金のテキスト情報のベクトル検索（Embedding）を組み合わせることで、より精度の高い提案が可能です。
